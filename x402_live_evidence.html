Description returned by the API:

Full flow and honest scope

  1. Request the resource → 402 Payment Required + accepts[] (real, captured above)
  2. Pick an accepts entry matching the agent's wallet network (both solana and base accepted)
  3. Sign the payment (EIP-3009 transferWithAuthorization on EVM, or a signed USDC transfer on Solana), base64 into X-PAYMENT
  4. Retry with X-PAYMENT → 200 OK + ranked quotes, with the settlement tx hash in X-PAYMENT-RESPONSE
  5. Pass the chosen providerQuote to /v1/swap/build-tx, sign, broadcast

What is claimed: only step 1 is executed and reproducible — regenerate anytime with a single POST. Steps 2–5 are documented, not executed: the linked agent wallet holds 0 USDC and its mandate requires a human signature, so no paid call or Solscan settlement tx is claimed. No full +30% bonus is requested; this is submitted specifically for the partial credit offered for a demo that runs part of the flow.
