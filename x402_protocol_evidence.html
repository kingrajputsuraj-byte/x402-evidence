transaction_simulation_failed means the facilitator parsed and simulated our signed transaction — it did not reject the payload as malformed or the signature as invalid. It failed because the payer's USDC ATA does not exist and holds 0 USDC. Per the API contract, failed requests are never charged.

4 · Honest scope

1. Request → 402 + accepts[]EXECUTED LIVE
2. Build + sign X-PAYMENTEXECUTED LIVE
3. Retry with X-PAYMENT → verificationEXECUTED LIVE
4. Settlement tx + Solscan linkNOT EXECUTED — 0 USDC
5. build-tx → sign → broadcast swapNOT EXECUTED — needs settled quote

The agent wallet holds 0 USDC on Solana mainnet. There is no paid call, no settlement transaction and no Solscan link, and none is represented as having happened. The full +30% "Make It Work" bonus is not claimed; this is submitted for the partial credit offered for a demo that runs part of the flow — here three of five steps, including a correctly-signed payload verified by the real facilitator.

An auto-settlement watcher is armed on the agent host: once the payer wallet holds ≥3007 atomic USDC it re-runs this client and appends the resulting Solscan link to the submission.
